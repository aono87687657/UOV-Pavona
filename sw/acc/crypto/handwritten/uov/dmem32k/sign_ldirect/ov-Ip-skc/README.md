# ov-Ip-skc: UOV-Ip signing (GF(256), v=68 o=44)

Last updated: 2026-10-20: how to run one parameter set and one tier.

## TL;DR
The Ip sign kernels and their unit harnesses; the cycles and memory of every tier are in
`../README.md` (Numbers).

## How to run
From the repository root, at the 32 KiB DMEM profile:
```
# One parameter set and one tier: Ip at bngfaes.
# Tiers: bngfaes, bngfonly, bnaesonly, sw.
./bazelisk.sh build //sw/acc/crypto/handwritten/uov/dmem32k/sign_ldirect/ov-Ip-skc:ov-Ip-sign_ldirect_testvec_bngfaes
python3 tools/gather_kat_stats.py --ops sign --params Ip --tiers bngfaes --variants ldirect --cases 0,11
```
For another tier, change it in the build label and in `--tiers`. It prints PASS and the cycles.

The three default tiers at once (bngfaes, bngfonly, sw), the kernel alone, and the cycles of one case:
```bash
./bazelisk.sh build //sw/acc/crypto/handwritten/uov/dmem32k/sign_ldirect/ov-Ip-skc:ov-Ip-sign_ldirect_testvec_{bngfaes,bngfonly,sw}
python3 tools/gather_kat_stats.py --ops sign --params Ip
# the ldirect kernel alone, ten edge cases
python3 sw/acc/crypto/handwritten/uov/dmem32k/sign_ldirect/ov-Ip-skc/run_ldirect_kats.py
# cycles for one case: statistics_0.txt in --output-dir
python3 \
  sw/acc/crypto/handwritten/own_utils/run_test.py sign --param Ip --tier bngfaes \
  --test-data-file sw/acc/crypto/handwritten/test_data/testvectors-Ip-pkc-skc \
  --case-start 0 --iterations 1 --output-dir /tmp/sign_ip
```
- `gather_kat_stats.py` runs prebuilt ELFs: `ov-Ip-sign_ldirect_testvec_<tier>`. Build first, or a stale binary
  passes.
- `run_ldirect_kats.py --cases 0-9` (the default; e.g. `--cases 0,3`) builds and runs each case of
  the kernel KAT on the ISS.

## Files
| file | role |
|---|---|
| `ov-Ip-skc-sign.s` | the ldirect sign body (the `_sprec` bodies are in `../../../dmem_large/sign_sprec/`) |
| `gf256_ldirect_68_44.s` | L = t^T·O + vin^T·P2 from one streamed P1 pass, with y = vin^T·P1·vin fused in |
| `gaussian_elimination_44x44.s`, `back_substitution_44x44.s` | the 44x44 solve |
| `gf256mat_prod_68_44.s`, `row_mul_O.s` | final matrix product, row times O |
| `expand352.s`, `expand_352_table.s` | the 352 B AES-CTR P1 stream (hardware AES, T-table; same output) |
| `expandv.s`, `hash_salted_msg.s`, `gf256_transpose_44_44.s` | vinegar KMAC, target hash, transpose |
| `gf256trimat_2trimat_madd_68_68_44_44.s`, `batch_quad_trimat_eval_gf256.s`, `gf256_matvec_2816_68.s`, `partial_expandP1*.s` | kernels of the precompute-S layout, linked from `../../../dmem_large/sign_sprec/` (`partial_expandP1*` also from `../../sign_rtl/`) |
| `*_test.s`, `ldirect_kat_test.s` | unit and kernel-KAT harnesses |
| `ldirect_test_inputs.s` | generated by `gen_ldirect_test_inputs.py`; never edit by hand |
| `run_ldirect_kats.py` | the ldirect kernel KAT runner |
| `AES_bngf/`, `AES_ttable/` | software AES for the bngfonly and sw tiers |

## Notes
- No Ip KAT case takes the retry after a singular elimination (chance about 1/256), so the
  `ge_failed` path is covered by review only.
- The sw tier's T-table AES makes data-dependent loads from a 4 KiB table: it is the baseline
  without instruction extensions, not a side-channel-safe or shipping configuration.
