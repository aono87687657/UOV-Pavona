# gf256: GF(2^8) multiply kernels, HW-instruction tests, measurement drivers

Last updated: 2026-10-28: `gf256_macc_dualvec_sw` tests each scalar bit once (in FG1); its unit test `gf256_macc_dualvec_sw_test`.

Software GF(256) multiply/MAC routines, tests for the HW `bn.gfmul.8` path (32 bytes per
op, `mod0` = AES poly 0x11b, `mod1` = scalar byte index in wrs2), and the isolation drivers
`GF_compare/` measures. Production: `gf256_sw_helpers` + `gf256mul_vxv_square` only (linked
by the Ip sw-tier keygen and sign ELFs); the rest is reference or rig.

## Files
| file | role |
|---|---|
| `gf256_sw_helpers.s` | production MAC/inverse helpers (`gf256_macc_sw`, `_batched`, `_dualvec`, `gf256_scalar_inv_sw`) + `msb_mask`; per-function contracts in the file headers |
| `gf256mul_vxv_square.s` | production per-byte squaring via the linearized squaring matrix; `gf256_scalar_inv_sw` calls it |
| `gf256_mul.s` | reference 32-byte vector × scalar, shift/xor + `bn.mulqacc` reduce |
| `gf256_mul_pqc.s` | same function, `bn.mulv.l.16H.lo` reduce instead; clobbers w16 |
| `gf256mul_vxv.s` | reference per-byte multiply of two 32-byte vectors |
| `gf256_{mul,mul_pqc,extmul,acch}_test.s` + `.exp` | bazel sim tests, fixed vectors |
| `gf256_macc_dualvec_sw_test.s` + `.dexp` | bazel sim test of `gf256_macc_dualvec_sw` on every scalar 0..255, values of a reference GF(2^8) multiply |
| `gf256_acch_test.exp` | GENERATED by `test_scripts/gf256_acch_expectgen.py`: never hand-edit |
| `gf256_*_rand_test.s`, `gf256mul_vxv*_test.s` | harnesses for the python checkers; operands injected into DMEM |
| `gf256_{gfmul,mul,mul_pqc}_op_test.s`, `gf256_setup_{hw,sw}_test.s` | measurement drivers + matching setup-only baselines |
| `test_scripts/` | python/sage checkers and the expect generator |

## Notes
- ACCSim models `bn.gfmul`/`bn.mulv` as 1 cycle. Measured 2026-07-22: `bn.gfmul.8` 1 cyc vs
  `gf256_mul` 100 / `gf256_mul_pqc` 79 for 32 bytes; setup (operand loads + mod CSRs)
  16 cyc HW / 18 cyc SW, per call site.
- Verify does not link from here: it ships the fork
  `uov/shared/verify/ov-Ip-pkc:gf256_mul_pqc_w16safe`. Edits here do not propagate to it.
- `acc_library` carries no deps: anything linking `gf256_sw_helpers` must also link
  `gf256mul_vxv_square`.
- The `*_rand_test` / `*_vxv_test` binaries are meaningless run bare: they read operands
  the python checkers inject. `gather_kat_stats.py` runs PREBUILT ELFs.
